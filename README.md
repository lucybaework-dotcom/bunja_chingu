# 분자친구 (임시 이름) — 프로토타입

같은 학교 학생이 원소 하나를 맡아, 실제 분자의 원소 구성대로 2~6명이 모여 친구가 되는 웹앱의 동작하는 프로토타입입니다. 서버 없이 브라우저 저장소와 가상 사용자로 전체 흐름을 시연합니다. 실제 다중 사용자 서비스가 아닙니다.

## 실행

```
npm install
npm run dev        # 개발 서버
npm test           # 규칙 테스트 (vitest)
npm run build      # dist/index.html 한 파일로 빌드
```

## 배포 (GitHub Pages)

`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml`이 테스트와 빌드를 거쳐 GitHub Pages에 올립니다. 처음 한 번 레포의 Settings → Pages → Source를 "GitHub Actions"로 설정해야 합니다.

## 구조

- `src/data/molecules.ts` 화학 데이터 (이름, 화학식, 원소별 원자 수, 총원자 수, 구조 키, 안정성 설명, 출처, 상태)
- `src/data/elements.ts` 편집용 성격 콘텐츠와 원소 간 보완·상극 세계관 (화학 데이터와 분리)
- `src/data/quiz.ts` 테스트 문항과 점수 규칙 (교체 가능한 설정)
- `src/domain/chemistry.ts` 화학식 일치 판정 (정확 일치, 상위 구성, 빈자리)
- `src/domain/recommend.ts` 보완성 추천 점수와 추천 이유 (임시 규칙)
- `src/domain/engine.ts` 모든 상태 전이와 권한 검사 (순수 함수)
- `src/backend/backend.ts` 서버 연결 지점. 화면은 `Backend` 인터페이스만 사용. `LocalBackend`는 이 기기 전용, `RemoteBackend`는 미연결 자리
- `src/backend/seed.ts` 가상 사용자 10명과 모집방 5개, 대기자 1명
- `src/ui/` 화면

권한 검사는 버튼 숨김이 아니라 `engine.apply` 안에서 합니다. 실제 서비스에서는 같은 규칙을 서버 트랜잭션 안에서 원자적으로 실행해야 합니다 (입장, 매칭, 확정, 카드 지급).

## 시연 도구

화면 오른쪽 아래 "시연 도구"에서 가상 사용자 화면으로 전환, 빈자리 채우기, 모집 마감, 투표 응답, 만남 확인, 대기열 추가, 초기화를 할 수 있습니다. 각 버튼은 해당 가상 사용자 본인 자격으로 명령을 보내므로 권한 규칙을 우회하지 않습니다.

## 미정 사항에 적용한 기본안

- 분자 카탈로그: 원자 2~6개의 작은 분자 22개. 출처는 PubChem CID를 구현자가 기재했고 화학 검수 전 `candidate` 상태입니다. 오존과 과산화 수소는 안정성 기준 검토가 필요해 `pending`으로 두고 매칭에서 제외했습니다. 검수 정책이 정해지면 `isUsable()` 하나만 바꾸면 됩니다.
- 원소: 카탈로그에서 실제로 쓰이는 H, C, N, O, Cl 다섯 개. 소듐 같은 원소는 염(NaCl)만 만들어 분자 규칙상 넣지 않았습니다.
- 테스트: 9문항, 평소 1 · 친구와 2 · 미래 1의 가중치. 선택지가 원소 점수를 직접 더하는 해석 가능한 규칙.
- 추천: 성향 축 3개의 차이(보완)를 우선하고, 다양성과 방 완성도에 작은 가산점. 유효한 분자 판정 뒤에만 쓰입니다. 대기 그룹은 가장 오래 기다린 사람이 들어가는 조합을 먼저 고릅니다.
- 모집 기한 기본 3일 (방 생성 시 1~7일 선택), 투표 응답 기한 24시간. 미응답은 동의 부족으로 처리.
- 방장 승계: 방장이 나가면 가장 먼저 들어온 남은 구성원.
- 재모집 충돌: 알림과 홈 경고를 띄우고, 남길 모집방을 직접 고르게 합니다. 고르기 전에는 새 모집에 참여할 수 없습니다. 기존 방을 일방적으로 지우지 않습니다.
- 첫 만남 전 이탈: 남은 구성과 정확히 같은 분자가 있으면 남은 사람 대상 투표를 열고, 반대하면 원래 목표의 빈자리를 다시 모집합니다.
- 만남 기록: 분자 완성 후, 첫 만남 한 건만 카드 대상. 참석자 2명 이상. 참석자를 고치면 기존 확인은 모두 무효. 같은 조성 분자가 여럿이면 카탈로그 첫 항목 (현재 카탈로그에는 해당 없음).
- 카드와 기록은 기본 비공개. 공개 화면에서도 동행자의 한 줄 소개는 숨기고 원소만 보여 줍니다 (동행자 동의 정책 미정).
- 한 줄 소개 최대 40자. 만남 기록은 기록 시점의 소개를 보존합니다.
- 학교 인증 없음. 하나의 가상 대학 안에서만 동작.

## 아직 연동이 필요한 부분

학교 인증과 계정, 서버 저장과 실시간 채팅, 푸시 알림, 기한 만료를 처리할 서버 작업, 화학 데이터 검수, 차단·신고·탈퇴 시 기록 정책.

## 검증

`npm test`로 30개 테스트가 통과합니다. 카탈로그의 표시 화학식을 다시 파싱해 원소별 원자 수와 일치하는지, 원자 수 2~6, id·구조 키 중복 여부를 확인하고, 기획서 검수 시나리오 1~13의 규칙(원소 고정, 자리 초과 금지, 자동 확정, 채팅 정책, 자동 매칭 순서와 방장, 모집방 하나 제한, 조기 완성·목표 변경 동의, 마감 종료, 이탈 처리와 충돌, 방장 전용 권한, 본인 확인, 카드 판정과 중복 방지, 공개 설정)을 상태 전이 단위로 검사합니다. 14번(금지 기능 없음)은 명령 목록에 원소 변경·개인 채팅·친구 추가·활동 선택 명령이 아예 없는 것으로 보장됩니다.
